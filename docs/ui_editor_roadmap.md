# VGUI 可视化 UI 编辑器重建规划

> 状态：旧 `vgui_editor` 原型已移除；新编辑器未实现。本规划不替代 [editor kit 组件路线图](editor_roadmap.md)，不改变 `vgui_editor_kit`、`<vgui/vgui_editor.h>` 或 `vgui_game_editor`。

## 1. 目标与取舍

新编辑器用于搭建 **VGUI 界面**（应用面板、表单、HUD），不是游戏场景编辑器。首期跑通一条路径：新建文档 → 放置控件 → 编辑结构和属性 → 检查不同视口下的运行时布局 → 撤销、保存、重新打开。按工作流增加能力，不以覆盖 `vgui.h` 的全部 setter 为目标。

旧原型把控件字段、JSON、C++ 导出、属性检查器和预览同步集中在 `gui/ui_editor.cpp`，同一个属性要在多个分支里分别维护；文档与选择还暴露可变的节点指针。重建不沿用这套接口：**文档是唯一可持久化的事实来源，预览控件树是可丢弃的派生结果，所有编辑走文档事务**。先保证模型正确，再分别实现工具界面和导出。

首期不做自由变换画布、任意插件或脚本、动画时间线、协同编辑、源码反向导入和 WYSIWYG 富文本编辑。运行时只依赖 VGUI；不用编辑器宿主来运行导出的界面。

## 2. 分层与依赖

以下目录和目标名为提案，不预占现有公共 API。先用内部 C++ 接口验证，暂不发布编辑器专属 C ABI。

| 模块 | 责任 | 依赖约束 |
| --- | --- | --- |
| `ui_design_model` | 文档、稳定节点 ID、控件与属性描述表、校验、编辑命令和 JSON 编解码 | 不依赖 VGUI 控件树、窗口或 GPU；可独立运行测试 |
| `ui_design_runtime` | 将通过校验的文档挂载到 `vgui_context`；资源和 action 由宿主解析；提供节点 ID 到预览控件的映射及布局快照 | 只依赖模型和 VGUI 公共接口，不依赖 editor kit 或 SDL |
| `vgui_ui_designer` | SDL3 宿主、面板、画板切换、选择/拖放、文件对话框、诊断 | 复用 Dock、Outliner、PropertyGrid 和命令设施；不把场景模型、3D 视口或 game editor 外壳搬过来 |
| `ui_design_export`（后续） | 同一文档和描述表生成目标产物 | 不依赖 shell 或活的预览控件，不读取用户机器上的工具状态 |

依赖方向为宿主 → 运行时 → 模型；导出只向下依赖。节点/属性描述表统一定义稳定的 `type_key` / `property_key`、值类型、默认值、约束、可用容器、检查器提示；运行时为这些键提供适配。测不准或做不到往返的属性不要先暴露在面板里。默认值有版本语义，不随编辑器主题或底层控件升级悄悄改变。

## 3. 文档、编辑事务与兼容

- **格式**：建议 `.vgui.json`，`format: "vgui-ui-design"`、`version: 1`、`root` 为稳定节点 ID。`nodes` 以 ID 为键，每个节点包含 `type`、可选显示名、`props` 和有序的 `children` ID 数组。父索引由 `children` 推导，不序列化指针；排序以 `children` 为准，不以 JSON 对象顺序为准。`resources` 用逻辑键映射项目相对路径；文本/l10n 和行为用数据键及 action ID，JSON 不执行代码。
- **校验**：解析到临时文档，校验版本、唯一 ID、有且仅有一个根、单父级、引用存在、无环/孤儿、允许的父子关系、值类型和资源路径，再替换当前文档。未知格式、未来版本、未知节点类型或属性给出带节点 ID/字段路径的诊断，不静默丢字段、不覆盖原文件。加载入口限制文件大小、深度和节点数；资源拒绝逃离项目目录。工具会话（Dock、缩放、选择）不写进交付文档。
- **事务**：新增、删除、复制、同父重排、重挂父级、改属性均以 ID 和具体差异表达。先验证整笔命令，再更新文档、撤销历史和预览；拖动只在提交时记一条，Esc 或焦点丢失时撤销临时反馈。禁止属性面板与画板分别维护撤销栈。保存点由文档历史标识跟踪，撤销回保存点应恢复干净状态；无效操作不得污染历史。
- **保存与迁移**：验证后同目录临时写入，成功后用平台支持的替换方法更新目标，失败保留旧文件及未保存状态。首期不直接打开旧 `vgui-ui-editor` v1 或自动覆盖旧文档；如确认有存量，再做一个显式的单向导入器，带导入报告、保留原件。本次不删除用户本地 JSON 或生成文件。

## 4. 工作台与真实预览

1. **组件库 / 大纲 / 属性 / 画板**：组件库只列已注册控件；大纲负责选择、层级与顺序；属性面板按描述表生成，并显示属性错误；画板提供缩放、平移、屏幕尺寸预设以及选中轮廓。启动只需这四个区域和一个状态/诊断入口。
2. **布局优先**：Row/Column 里的拖拽走插入位/重排，编辑 gap、padding、grow、对齐；只有 Absolute 容器支持拖动 XY 和改尺寸。跨容器拖放先验证目标，再提交一次重挂父级；不把 Flex 排版结果反写成绝对坐标。画布缩放不改变内容视口的逻辑尺寸，也不改文档。
3. **一个布局真相**：通过 VGUI 真实布局计算矩形、裁剪和基线。首期允许完整重建预览；纯属性更新先走适配器，结构变更分阶段优化，不先许诺所有变更都能原地重挂。用独立预览 `vgui_context`；SDL3 宿主可复用现有离屏渲染目标显示预览，模型和挂载测试仍可 headless 跑。预览结果记录文档 revision 与坐标变换，外壳选框/命中只使用同一轮布局快照；旧快照不驱动编辑。
4. **设计/运行模式**：设计模式拦截选区和拖放操作；运行模式将转换过的输入交给预览控件，按钮、焦点、编辑框和滚动按真实运行时工作。预览中的临时输入值不直接写回文档；切回设计时从文档恢复。Preview 与导出使用相同资源键、逻辑尺寸和控件默认值，不为编辑器另写布局引擎。

## 5. 实施顺序与验收

| 阶段 | 交付物 | 验收门槛 |
| --- | --- | --- |
| U0：模型与文档 | 基础类型描述表、版本化 JSON、节点 CRUD/重挂及撤销、保存/校验 | Headless 验证规范化往返、坏数据不覆盖、拒绝环/重复 ID、保存失败保留原件；撤销/重做恢复结构与保存状态 |
| U1：运行时挂载 | Panel、Label、Button、Edit、Image；Absolute/Row/Column；宿主资源/action 回调及 ID 映射 | Core-only 从固定文档构建树，断言在至少两种视口宽度及 1×/2× DPI 的控件矩形；资源未就绪有可诊断占位，运行态不回写文档 |
| U2：可操作编辑器（MVP） | SDL3 工作台、大纲与检查器、画板、设计/运行切换、文件新建/打开/保存及未保存提示 | 原生端到端：创作带嵌套布局和图片的表单、改属性和重排、撤销、保存重开；小视口不把响应式布局转绝对定位；取消/错误导入不损坏文档 |
| U3：可交付产物 | 出包时先提供可校验的文档和显式资源清单；如确需独立 C++，再生成只调用 VGUI 公共接口的代码 | 同一输入可确定生成；在独立消费者构建、加载并校验界面结构和代表性矩形与预览一致；不依赖 editor kit 和工作区绝对路径 |
| U4：扩展 | 组件复用/主题令牌、更多控件、数据绑定、富文本与行内图、必要时旧版单向导入 | 每类扩展补数据往返、预览与导出一致性；性能先做基线（大纲/选取/拖动/重建），再按实际瓶颈增量化 |

下一步只做 **U0**：先落一个可解析、校验、往返并支持撤销的最小文档和 headless 测试，不先写大而全的画板、代码生成器或应用外壳。
